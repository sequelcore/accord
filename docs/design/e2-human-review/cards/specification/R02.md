# R02

Review a verdict for one file's proof. Inputs are its outcome, a failure text,
and the failure texts already sent back. Text membership uses exact equality.
Passed must give Proved. Failed or Vacuous gives SendBack for a new failure and
NoProgress for an already-sent failure. TimedOut, Cancelled, and NotStarted must
give Operator. All enum outcomes and all texts/lists are admitted. The result
is advisory; this pure function does not itself retry, stop, or contact anyone.

Find requirement violations or missing promises. Give a concrete input and
required result, or an excluded-input witness. Say which claim is affected.
Choose accept, request_change, or insufficient_information. If an artifact
cannot reveal a defect, say not_observable. After the task, rate confidence
0–100. Time limit: eight minutes. No tools, source browsing, or other packets.

```accord
enum ProofOutcome { Passed, Failed, Vacuous, TimedOut, Cancelled, NotStarted }
enum GateVerdict { Proved, SendBack, NoProgress, Operator }

fn gate_verdict(outcome: ProofOutcome, failure: Text, sent: List<Text>) -> GateVerdict
    intent "Accept a passed proof; send a failed or vacuous proof back once per failure; identify repetition as no progress; ask the operator about interrupted or unstarted work."
    ensures result == Proved implies outcome == Passed
    ensures outcome == Passed implies result == Proved
    ensures result == SendBack implies (outcome == Failed or outcome == Vacuous) and not failure in sent
    ensures (outcome == Failed or outcome == Vacuous) and not failure in sent implies result == SendBack
    ensures result == NoProgress implies (outcome == Failed or outcome == Vacuous) and failure in sent
    ensures (outcome == Failed or outcome == Vacuous) and failure in sent implies result == NoProgress
    ensures result == Operator implies outcome == NotStarted or outcome == TimedOut or outcome == Cancelled
    ensures outcome == NotStarted or outcome == TimedOut or outcome == Cancelled implies result == Operator
```
